# 给杨若璇的留言簿

杨若璇。

在线网站：https://yang-ruoxuan-guestbook.spiffy-berry-3280.chatgpt.site/

仓库的 `main` 为当前完整网站源码，包含前端、七张图片相册、共享留言后端、数据库迁移与运行说明。

一个以深色星空为背景的公开留言簿。首屏只突出名字，以六条交错轨道展示姓名与不同语言的“我爱你”。背景提供星点漂移、轻微闪烁、鼠标视差、局部星座连线与柔和光晕；手机端降低粒子密度。顶部暂停按钮同时控制弹幕和星空；支持减少动态效果偏好和后台暂停。保留留言分页、昵称与内容校验、发布状态和错误提示，访客无需注册。语言数据及来源说明见 `languages.json`、`LANGUAGE_SOURCES.md`。

弹幕姓名会采用相应语言的字形/音译，未核对到可靠当地写法时使用 `Yang Ruoxuan`。部分文字形式为展示用近似拟音，并在数据的 `nameForm` 和来源说明中标明；中央姓名仍是中文原名。

名字下方、留言区上方展示七张用户图片，采用独立白边、宽窄不同、轻微旋转的实体照片拼贴。保留各自横竖比例，七张同时可见，只遮挡局部。约每5.6～7.8秒轻轻抬起其中一张到前方，每轮遍历全部七张，排列有小幅自然变化；点击任意照片也可将它置于前方。手机端使用独立的错落布局；底部仅保留编号、左右按钮和暂停，不显示缩略图列表。支持键盘和手机横向滑动；悬停、键盘焦点、离屏、后台、全局暂停或减少动态效果偏好都会停止自动切换，明确点击播放可恢复。未给照片添加虚构的时间或故事文案。

## 项目结构

原仓库是纯静态 HTML 网站，本次继续使用原生 HTML、CSS 和 JavaScript，没有引入前端框架。在此基础上补充 Cloudflare Worker API 和 D1 数据库存储。

| 文件或目录 | 用途 |
| --- | --- |
| `index.html`、`styles.css`、`guestbook.js` | 留言簿界面与交互 |
| `marquee.js`、`languages.json`、`LANGUAGE_SOURCES.md` | 多语言弹幕、数据及来源归属 |
| `constellation.js`、`space.css` | Canvas星空、指针交互和深空/蓝调配色 |
| `gallery.js`、`gallery.css`、`photos.json`、`photos/` | 七张白边照片拼贴、动态选中交互和经过压缩的WebP图片 |
| `worker/index.js` | 页面、静态资源路由和安全响应头 |
| `worker/guestbook.js` | 共享留言 API、签名表单令牌和防刷校验 |
| `db/`、`drizzle.config.ts` | 生产数据库结构与迁移生成配置 |
| `migrations/0001_guestbook.sql` | 本地 SQLite 初始化结构 |
| `scripts/dev.mjs`、`scripts/build.mjs` | 本地服务与 Worker 构建 |
| `tests/` | 真实 SQLite API 测试、构建产物与静态规则检查 |
| `.openai/hosting.json` | Sites 项目标识和 D1 逻辑绑定，不存放密钥 |

旧小游戏页面及旧图片、音效素材已从当前代码中清理。网站图片位于 `photos/`，以二进制响应提供，使用内容哈希文件名和长期缓存。七张主图与缩略图总计约1000KiB，没有把原始PNG大图直接带给访客。旧代码仍可从 Git 提交历史中恢复。

## 本地运行

需要 Node.js **22.13 或更高版本**和 npm：

```sh
npm install
npm run dev
```

默认访问 `http://127.0.0.1:4173`。可通过 `PORT` 环境变量指定其他端口。开发服务器只监听本机回环地址，不是公网部署。

开发服务将留言持久保存在忽略提交的 `.data/messages.sqlite`。关闭或重启服务不会删除留言；删除此文件则会清空本地数据。默认生成的本地签名密钥只在当前开发进程有效，重启后需刷新旧表单。可在启动进程的环境中设置 `SIGNING_SECRET` 以保持令牌签名密钥固定。

```sh
npm test
npm run build
```

测试覆盖真实 SQLite 中的写入、查询、分页和防刷边界，同时检查构建出的 Worker 路由、错误状态、安全响应头、表单关联和响应式 CSS 规则。静态规则检查不等同于真实手机端视觉验收。

构建产物是 `dist/server/index.js`，页面和样式嵌入 Worker；`dist/` 是生成目录，不应手动修改。`npm start` 运行本地开发服务，不会自动发布网站。

生产构建会给脚本和样式生成包含内容哈希的独立地址，首页返回 `Cache-Control: no-store`，避免重新打开时继续使用更新前的脚本。已经打开的旧页面仍需重新加载一次；本地预览继续使用原文件路径。

## 数据存储与安全

`https://yangruoxuan.ltd` 和 `https://www.yangruoxuan.ltd` 是静态前端入口，无法直接执行此仓库的 Worker API。前端识别这两个域名后，会直接连接 `https://yang-ruoxuan-guestbook.spiffy-berry-3280.chatgpt.site` 的共享留言 API；服务端仅为这两个精确的HTTPS来源返回CORS许可和预检响应，不使用通配来源，不携带浏览器Cookie。两个入口使用同一份既有数据库，无需复制留言。字体CSS直接引用仓库中真实存在的哈希字体文件，静态部署也能加载。

首页响应会在服务器内读取第一页留言，安全地附在页面的数据块中；浏览器优先使用这份初始数据，首次展示不再依赖额外的留言读取请求。刷新和分页仍使用 API；所有昵称与内容继续以纯文本生成卡片，内嵌数据中的HTML结束标记会被转义，首页不缓存。

读取列表与申请表单令牌在临时网络错误或异常响应时最多尝试三次；网络恢复、重新聚焦或返回标签页时，会重试之前失败的读取。发布请求不会自动重发。若写入已经成功但响应丢失，在原令牌有效期内手动重试完全相同的昵称与内容，会恢复同一条记录，不重复写入；修改内容、作者或使用其他客户端均不能借此恢复记录。

未发布的昵称和内容暂存在当前标签页的 `sessionStorage`，刷新后可恢复；只有服务器确认发布成功才清空草稿内容。存储不可用时，当前表单仍可使用。共享留言本身仍保存在服务器数据库。

界面使用本站托管的可变无衬线字体（`typography.css`、`fonts/`），覆盖常用中文、站点文字和基本拉丁文字，缺字回退至系统无衬线字体。字重为300～600，字体来源、子集说明和OFL许可证位于 `fonts/README.md`，访客不依赖外部字体服务。

- **生产环境**：留言保存在此 Sites 项目绑定的 Cloudflare D1 数据库 `DB`，不同设备、浏览器和访客访问同一份数据。
- **本地环境**：使用 `.data/messages.sqlite`，与生产 D1 分开；本地留言不会自动上传到生产，生产留言也不会同步到本地。
- 昵称为 1～24 个 Unicode 字符，内容为 2～500 个字符；服务端再次校验长度、异常控制字符、网址、请求来源和请求体大小。
- 留言按纯文本处理，前端通过 `textContent` 显示；用户输入不会被当作 HTML 或脚本执行。
- 表单使用短时签名令牌、至少两秒的提交等待、一次性 nonce 和隐藏防刷字段。按来源 IP 的不可逆 HMAC 标识限制发布：每次至少间隔 **45 秒**，每小时最多 **10 条**；24 小时内拒绝该来源的重复内容。
- 不记录原始 IP。共享网络出口的访客可能共用防刷配额，这些措施也不能完全阻止人工或分布式垃圾留言。
- 浏览器存储只用于外观偏好，留言不会降级为 `localStorage`。数据库或密钥不可用时，服务返回错误，不会伪装发布成功。

留言会公开展示。站点没有访客登录、私信或私密留言功能，也没有暴露公开删除接口。

## 生产配置与部署

本项目配置了 Sites 的 Worker 发布方式。发布需要拥有对应 Sites 项目的账户权限和源码仓库授权；向原 GitHub 仓库推送还需要该仓库的写入权限。`.openai/hosting.json` 的 `d1` 应为字符串 `"DB"`，Worker 构建不声明静态托管模式。

在托管平台的**服务端运行时环境变量**中配置：

| 名称 | 要求 |
| --- | --- |
| `SIGNING_SECRET` | 至少 32 个字符的随机密钥；只配置在服务端，不能写入前端文件、GitHub 或 hosting manifest |

使用 `.env.example` 了解变量名称；源码不会自动加载本地 `.env`。生产缺少密钥或数据库绑定时，留言服务会返回 503。

若修改数据库结构，更新 `db/` 中的声明后运行 `npm run db:generate`，审查并提交生成的 SQL 和 Drizzle 元数据。Sites 打包识别根目录 `drizzle/`，将迁移随产物上传并在发布时应用到生产 D1。已应用的迁移不要改写，后续结构调整新增迁移。

公开匿名访问还需要将 Sites 的访问范围设为公开；私有 Sites 仍会由平台要求登录。该访问设置与留言簿自身“不注册即可留言”的设计是不同层次。

**此 README 不将预期域名或本地预览地址视为部署成功。** 公网部署是否完成、最终地址及授权情况，以实际部署结果为准；没有真实部署成功结果前，不应对外宣称已经上线。

### 备份与管理

网站所有者可通过有权限的 Sites 数据库工具查看生产 D1 的表和记录。生产备份、导出与管理应在对应托管平台或数据库管理权限下完成；删除错误留言需由所有者在数据库中按记录 ID 操作，不应给公开前端添加数据库密钥。

本地备份时先停止开发服务，再备份整个 `.data/` 目录，避免遗漏 SQLite 的 WAL 文件。不要把备份、数据库文件或运行时密钥提交到 GitHub。源代码备份不能替代留言数据备份。

Vercel、Netlify、GitHub Pages 都不是本项目当前 Worker 产物的直接运行环境。若更换平台，需要另外适配后端和共享数据库，不能只发布静态首页后宣称留言已经持久化。平台当前额度与费用以其账户控制台为准，本项目不承诺永久免费。
